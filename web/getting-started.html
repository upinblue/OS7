Getting started

From the ISO to a machine that boots.

About twenty minutes on a virtual machine, most of it spent unpacking. Setup takes the whole disk it is given and asks once, on screen 6, before it writes anything at all.

  1. Download and verify the image

    Take the ISO for your architecture from the download page and compare its SHA-256 sum with the one published beside it. A truncated download produces an installer that fails in the middle, and that failure looks like a bug in OS/7 rather than a bad copy. 

    Get-FileHash .\OS7-<version>-amd64.iso -Algorithm SHA256

  2. Write it, or attach it

    In a VM, attach the ISO and give the machine UEFI firmware, 4 vCPUs and at least 6 GB of RAM for x86-64. On hardware, write the ISO to a USB stick byte for byte — on Windows that means Rufus in DD Image mode, not the default.

  3. Turn Secure Boot off, and boot the medium

    The setup medium’s bootloader is unsigned, so firmware with Secure Boot on will not start it. The installed system does boot with Secure Boot on, so switch it back afterwards. There is no BIOS or CSM path — UEFI is required, not preferred.

    The boot menu offers Install OS/7 and a live session. Pick the first.

  4. Walk Setup

    Twelve screens, driven entirely from the keyboard: ↑ ↓ to choose, Enter to continue, Esc to go back, F3 to quit. Language and keyboard come first, then the disk, then the layout and the disk passphrase.

    Screen 6 is the gate. It lists everything that is about to be written — the disk, the partitions, the pools, the datasets — and nothing has touched the disk before you confirm it. After that, Setup creates the first account, asks whether this machine is a desktop or a headless server, and configures the network.

  5. Let it install, then reboot

    The execute screen names each step as it runs and stops on the first one that fails, with the log path on screen. When it finishes, remove the medium and reboot: the disk boots on its own, and asks for the disk passphrase unless the machine has a TPM 2.0 that OS/7 could enrol.

  6. The first prompt

    Log in and you are in PowerShell — on the console, over ssh, and in the desktop’s terminal window. Start here: 

    Get-OS7Version                 # what this machine is, exactly
Get-Command -Module OS7        # everything OS/7 adds
Get-OS7BootEnvironment         # what it can boot, and what it booted

  7. Know how to go back before you need to

    OS/7 keeps the previous boot environment. If an update leaves the machine wrong, roll back — and if it will not boot at all, the previous environment is an entry in the boot menu. 

    Get-OS7BootEnvironment              # list them
Restore-OS7 -WhatIf                 # what a rollback would do
Restore-OS7                         # activate the previous one, then reboot

Where the rest of it is

OS/7 is developed in the open, and the documents that decide things are in the repository rather than paraphrased here. If a page on this site and a document there ever disagree, the document is right.

  • The repository — source, build, and the full status table
  • SETUP-PLAN.md — the installer: every screen, every decision, every known limitation
  • DECISIONS.md — what is locked, and what is still open
  • BUILD-NOTES.md — every trap found so far, numbered, with the evidence
  • Issues — where a preview build that misbehaves should be reported
A bug report that names the version from Get-OS7Version and the architecture is worth several that do not. The version identifies the exact package set the machine holds, which is the point of pinning the archive in the first place.
