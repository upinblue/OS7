For organizations

Linux that your existing controls already understand.

OS/7 is aimed at IT departments, managed service providers and Microsoft-centric organizations — not at consumers looking for a daily driver. The design rule is blunt: where a technical preference and an Intune constraint collide, Intune wins.

One compliance story

Encryption is LUKS2 because Intune only recognises dm-crypt. Devices report through the same portal as the Windows fleet, with the same encryption and firewall checks.

One skill set

Administration is PowerShell, on the console and over ssh. Nothing has to be re-learned to list a disk, take a snapshot or check a backup.

An undo for patch night

Updates land in a clone of the running system. A machine that comes back wrong is rebooted into the previous environment — not rebuilt from an image.

Reproducible releases

Every release pins the Ubuntu archive to one timestamp. Two machines reporting the same version hold the same packages — on the day of the release and a year later.

Scope

Two architectures, two different products.

This is not a packaging detail, and it is worth knowing before a pilot is scoped. Microsoft ships no arm64 build of Edge, the Intune portal or the identity broker, so arm64 cannot be an Intune-managed desktop no matter what OS/7 does.

Identity and management

The estate keeps one directory.

Sign-in goes to Entra ID through authd and the Microsoft Entra broker, with a local break-glass account for the day the tenant cannot be reached. Devices enrol in Intune; servers register with Azure Arc and appear in the same resource graph as the rest of the subscription.

/etc/os-release is deliberately left Ubuntu-identifiable, so an Allowed distributions rule that already lists Ubuntu 26.04 keeps matching. The OS/7 branding lives in fields that no Microsoft tool reads — a decision taken after finding that three Microsoft consumers read three different sets of those fields.

Entra ID sign-in is the one piece that does not work yet. The broker is shipped by Canonical as a snap, and it cannot yet be placed inside the image.

Operations

Patching, rollback and backup are one story.

An update is applied to a clone of the running boot environment, not to the running system. Two environments are kept, so Restore-OS7 always has somewhere to go back to, and the previous system is in the boot menu for the case where the new one does not come up at all.

User data sits on its own datasets, snapshotted on a policy and replicated off the machine over ssh. The scheduling and the replication are sanoid and syncoid — not reimplemented — but the verification is OS/7’s own, because both tools report success in cases where nothing happened.

Backup is written and self-tested offline. It has not yet been run against real hardware, and the project says so rather than implying otherwise.

What is not there yet

The list matters more than the feature list, because a pilot plan built on the feature list alone will hit these in week one.

Entra ID sign-in
Does not work. The authd-msentraid broker is a Canonical snap and cannot yet be built into the image.
Secure Boot and rollback on x86-64
Both work on arm64 and are proven by scripted tests. On x86-64 they are untested, because the test harnesses are aarch64 emulators and no x86_64 equivalent has been written.
The update train
Written, checked offline, never run on a machine — and waiting on there being a published release to apply.
Backup
Written and self-tested. Never run against real ZFS on real hardware.
Support
There is no support contract to buy today. See below.
