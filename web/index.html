A Linux that speaks Microsoft.

PowerShell is the shell you type in. Entra ID signs people in, Intune and Azure Arc manage the machine, and a ZFS root means an update that goes wrong is one reboot away from being undone. Ubuntu 26.04 LTS underneath, left alone where it matters.

OS/7 has not been released. Both architectures install and boot today, and the x86-64 desktop runs Edge, the Intune portal and VS Code — but Entra ID sign-in does not work yet, and rollback is untested on x86-64. Please do not put this on hardware you care about. What works, in detail.

Why it exists

Linux is usually the exception in an otherwise Microsoft-shaped estate.

Entra ID for identity, Intune for devices, Azure Arc for servers, PowerShell for administration — and then a workload needs Linux, and it arrives with its own tooling, its own way of proving compliance, and its own row in the audit. OS/7 is Ubuntu, set up so that it fits that tooling instead of sitting beside it.

The shell

You log in and get a PowerShell prompt.

On the console, over ssh, and in the desktop’s terminal window — PS /home/you>, PowerShell 7.6, with the OS/7 cmdlets already loaded. Scripts an admin already owns keep working.

bash stays the system shell. cron, systemd units, dpkg hooks and Intune’s own bash compliance scripts are untouched by this, which is the point: the interactive shell changed, not the plumbing.

Management

It enrols in Intune. Servers report to Azure Arc.

The x86-64 desktop carries Microsoft Edge, the Intune portal and the identity broker, because Microsoft requires all three for enrolment. arm64 is a server product and is managed through the Azure Connected Machine agent instead.

Microsoft’s requirements shaped the design rather than being worked around afterwards: disk encryption is LUKS2 because Intune only recognises dm-crypt, and /etc/os-release stays Ubuntu-identifiable so the Allowed distributions rule keeps matching.

Updates

An update you can take back.

The root filesystem is ZFS on LUKS2. An update is not applied to the running system: it is applied to a clone of it. The machine reboots into the new environment, and the old one is still there, still bootable, listed in the boot menu.

If something is wrong, you pick yesterday’s entry at boot, or run Restore-OS7. Snapshots, clones, boot environments and off-machine replication are all driven from PowerShell.

Setup

An installer that suits a headless server and a desktop equally.

os7-setup is keyboard-driven and text-mode, styled after MS-DOS 6.22 Setup and the Windows 2000 text phase. That is not only nostalgia: a 4.4 MB binary with no graphics stack behind it runs the same over a serial console as it does on a monitor, and installs the desktop-less arm64 image that a Qt installer never could.

Twelve screens: language and keyboard, disk, partition layout and passphrase, a confirmation gate before anything is written, account, GUI or headless, network.

The desktop

OS/7 Classic, for people who came from Windows.

The x86-64 desktop is GNOME with a Windows 2000 surface: a task list, a start menu, square window frames, a system tray. It is built from GNOME’s own Classic extensions rather than third-party shell hacks, so an Ubuntu release upgrade leaves it intact instead of breaking it.

Nothing phones home. The first-login wizard, ubuntu-report, ubuntu-insights, whoopsie, apport and Firefox are removed and pinned at Pin-Priority: -1, so a later apt full-upgrade cannot quietly restore them.

The two architectures are deliberately different products. Microsoft ships no arm64 build of Edge, the Intune portal or the identity broker, so arm64 is a server and is managed through Azure Arc. The full table, and the evidence behind each row, is in the repository.
