# The OS/7 administrator manual

Two languages, one source. Markdown is what is edited; the PDF is a rendering
of it, so no sentence lives in two places.

```
de/                  the German chapters, in filename order
en/                  the English chapters, the same order
images/              screenshots and diagrams
transcripts/         what the machine printed, per screenshot
build-pdf.py         Markdown  ->  one A4 PDF per language
make-diagrams.py     the SVG diagrams, both languages from one layout
make-reference.py    Appendix A, generated by asking the modules
```

## Rebuilding

```bash
python -m pip install markdown playwright        # once
python docs/manual/make-diagrams.py              # the SVGs
python docs/manual/make-reference.py             # Appendix A, needs pwsh
python docs/manual/build-pdf.py                  # both PDFs
python docs/manual/build-pdf.py de --html        # one language, HTML only
```

`build-pdf.py` prints through **Microsoft Edge**, driven by Playwright with
`channel="msedge"` — nothing is downloaded, and the DevTools protocol is what
makes a footer with page numbers possible at all (`msedge --print-to-pdf`
cannot set one).

The version on the title page is read out of
[`build/config/os7-release.conf`](../../build/config/os7-release.conf), because
that is the only place in this repository a version number may live.

## Where the pictures come from

**The cmdlet screenshots and the transcripts beside them were taken from a
machine**, by `installer/testing/shoot-manual.py`: it boots an installed OS/7
disk with no medium attached, logs in the way a person does, and records what
the console printed. Both artefacts come out of the same bytes —
`transcripts/NN-name.txt` is the screen's text, `images/NN-name.png` is the
same screen drawn with the font the image ships
(`/usr/share/consolefonts/os7-console-16x32`, Cascadia Mono, decision D15) and
the kernel's own sixteen colours. 80x24, the console's own geometry.

```bash
python installer/testing/shoot-manual.py            # boot .vm/manual, take every shot
python installer/testing/shoot-manual.py --render   # re-render from the saved bytes, no VM
```

The typed command is cut out of each picture before it is drawn, and the reason
is in that file's `trim_echo`: PSReadLine repaints the line being edited with an
absolute cursor move to the row it believes the prompt is on, and a terminal
replaying only one command's slice starts empty, so every one of those moves
lands wrong. The manual prints each command in a code block immediately above
its picture instead. A reconstructed prompt line would be a drawing of
something the machine did not send.

**The Setup screenshots come from a machine too**, and until 2026-09-22 they did
not. `run-phase3.py walk` boots the medium in a VM and walks the whole flow by
keypress — welcome, licence, regional, disk, layout, passphrase, the gate,
account, mode, network, the executor, complete — and installs from it;
`place-manual-shots.py` then files those screens under the names the chapters
reference:

```bash
python installer/testing/run-phase3.py walk
python installer/testing/place-manual-shots.py setup
```

The placer owns the MAPPING, and it verifies rather than trusting it: every
picture is read back through the console font the screen was drawn with and must
carry a phrase from that screen, and the version in the title row is checked
against the medium's own `release.json`. A picture of the wrong screen under a
right-looking name fails; so does a picture of another build.
`--check` reads and places nothing.

The predecessors were **1.0.0.116's**, which is printed on the pictures
themselves, and they came from `os7-setup` run in a chroot with `lsblk` shadowed
and `/sys/class/net` laid out by hand — so the disks and adapters on screens 4,
5, 6 and 9 were a fixture rather than a machine's. The new ones show a virtual
machine's `vda` and `vdb` and its `virtio_net` adapter, which is less like a
laptop and true.

**The desktop screenshots** come off a GUI bench, signed in at the greeter and
driven through QMP:

```bash
python installer/testing/os7lab.py install gui --mode Gui   # once, ~25 min
python installer/testing/os7lab.py up gui
python installer/testing/shoot-desktop.py
python installer/testing/place-manual-shots.py desktop
```

`shoot-desktop.py` accepts nothing on the operator's behalf — Edge's first-run
consent dialog and the Intune sign-in are photographed as they arrive — and it
writes `provenance.txt` beside the pictures, naming the machine's own version,
because a desktop picture cannot be read back through a console font the way a
Setup one can. The placer refuses a desktop set without that file.

It also checks their geometry and that no single colour covers more than 80% of
the frame. That last rule is not decoration: the picture chapter 13 used to
caption *"The OS/7 desktop in its classic appearance"* was 94.7% pure black — a
panel and a status bar on a void — and it had been in the manual for three
weeks. The desktop is black on purpose; a picture of it alone is a picture of
nothing, so the set shows the start menu open instead.

The Setup pictures have `transcripts/setup-*.txt` beside them, from the same
pixels, for the same reason the console ones do: what is on a screen should be
greppable without opening a PNG.

**The diagrams** are generated by `make-diagrams.py`. Every box in them names
something that exists — a dataset the installer creates, a file the build
writes — and each function's docstring says which document the facts came from.

## Appendix A

Generated by asking the modules, the same way
[`../POWERSHELL-REFERENCE.md`](../POWERSHELL-REFERENCE.md) is: every name,
synopsis and parameter list comes out of `Get-Command` and `Get-Help`. A cmdlet
missing from the appendix is missing from the product. Re-run
`make-reference.py` after any change to the module surface.
