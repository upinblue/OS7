# Session — the administrator manual, and what writing it measured

**2026-08-29, x64 Windows host.** An administrator manual was written for OS/7
in German and English, and the exercise turned out to be a test of the product
rather than only a documentation task. This records what was measured, what was
not, and what it changes.

## 2. The method, and why the pictures are evidence

The repository's rule is *measure, don't assert*, and a screenshot is a claim
like any other. So none of the cmdlet pictures were composed:
`shoot-manual.py` boots **`.vm/manual`** — a copy of the installed disk
`run-s5.py`'s gate produced — with no medium attached, logs in as a person
does, and records the console.

Two artefacts per command, from the same bytes: `transcripts/NN.txt` is what the
screen held, `images/NN.png` is that screen drawn with
`/usr/share/consolefonts/os7-console-16x32` (Cascadia Mono, D15) and the
kernel's own sixteen colours. It is the method `out/screenshots/README.md`
describes for its `console/` set, reused rather than reinvented — the renderer
is that directory's `os7shot.py`, loaded with its container-time `REPO`
constant repointed at this checkout and its POSIX-only imports dropped, because
this host is Windows and `Vt`, `Font`, `palette` and `render` never touch them.

**What is real and what is not.** Every character came off the machine's serial
line at 80x24. Two things are arranged and both are stated in the harness: a
`Clear-Host` before each command, so a picture holds one command rather than the
tail of the previous one; and the typed command is cut out before the picture is
drawn (#114). The manual prints each command in a code block above its picture
instead — a reconstructed prompt line would be a drawing of something the
machine did not send.

**The TPM did not unseal**, and that is not a finding about the product. The
copied `.vm/manual/tpm` state and the copied disk are a different machine as far
as the seal is concerned; the harness types the passphrase and says so.
`run-s5.py boot` remains where that claim is measured.

## 3. What it found

Three numbered entries, all in [BUILD-NOTES.md](BUILD-NOTES.md).

### #112 — `Get-OS7BackupStatus` throws on an ordinary machine

Asked for a picture of the backup status, the machine answered:

```
Get-OS7BackupStatus: The property 'NewestReplicated' cannot be found on this object.
```

`Select-Object -Last 1` over an empty pipeline is `$null`, and `OS7.psm1` sets
`Set-StrictMode -Version Latest`. `$targets` is empty whenever no replication
target exists — which is every machine that has not opted in, replication being
opt-in by B4 — and unconditionally so under `-SkipTargets`.

The same shape sits one line above on `$newestLocal`, and that one fires on a
machine whose first snapshot has not run yet: **the first status a new
installation is asked for is the one that cannot be given.**

Sixty lines up, the same file carries a comment about this exact strict-mode
trap. The knowledge was written down and the code below it did the other thing.

### #113 — the surface cannot see a timer, and §6's update check is one

`Get-OS7Service` pins `Type = 'service'` with no way to widen it, so
`os7-update-check.timer` — installed, and the half that does the work — cannot
be seen at all. The `.service` half appears and reads `inactive/dead`, which is
correct for a timer-pulled unit and tells an operator nothing.

`Set-OS7Service -StartupType` reaches a type-agnostic helper, so **enabling the
timer works and looking at it does not.**

### #114 — a replayed terminal slice must match the guest's geometry

Three harness runs produced unusable pictures before the rule was clear:
the emulator's size, and where the slice starts, have to match what the guest
believed when it emitted the bytes. Details and the table of symptoms are in the
entry. `Remove-Module PSReadLine` does not help — the host brings it back for
the next prompt, and the byte stream shows it.

The same run also re-learned #16 in a third costume: `sudo stty` needed no
privilege, sudo asked for a password, the harness was not waiting for one, and
the next command was typed into the prompt.

## 4. What the manual corrected in itself

Appendix A is generated by asking `Get-Command` and `Get-Help`, and that is what
stopped the chapters inventing parameters. Caught before publication:

* `New-ZfsSnapshot` takes `-Name` and `-SnapshotName`, not `-Dataset`.
* `Get-OS7Log` has `-Tail`, not `-Last`, and returns the journal's own fields.
* `Get-OS7Service` has `ActiveState`/`SubState`; a first draft asked for a
  `State` column and produced an empty table on a healthy machine.
* `Test-OS7Network` returns **one** object with an `Endpoints` property, not a
  collection.
* `Get-OS7Endpoint` names are `Entra`, `Graph`, `Intune`, `Arc`.

And one trap that nearly reached print, now a warning box in chapter 9:
**`Healthy` is `$null` without `-Detailed`, not `$false`**, so
`Where-Object { -not $_.Healthy }` matches every service. The idiom appears in
this repository's own examples.

Two rendering faults had the shape this repository keeps meeting — a
transformation that matched nothing and reported success. The figure pattern
assumed `<img src= alt=>` while python-markdown emits `<img alt= src=>`, so all
63 captions were dropped and the document still built; `build-pdf.py` now
refuses to emit a document in which no image became a figure.

## 5. What was NOT measured

* **arm64.** Every picture is amd64. Nothing in the manual is arm64-verified.
* **The desktop.** Chapter 13's pictures are the 1.0.0.116 set from
  `out/screenshots/`; no desktop was driven in this session.
* **Anything the manual describes that has never run** — the domain join, the
  backup replication, `Restore-OS7File`. Those chapters are written from the
  code and the plans, and the manual does not say so.
* **The machine's release.** The pictures are of 1.0.0.148; the pin is at
  1.0.0. Re-run `shoot-manual.py` when the surface changes.
